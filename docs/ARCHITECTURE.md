# Архитектура и дорожная карта

Актуально на 15.09.2026. Высокоуровневые решения (push/poll-обмен с 1С,
зеркало в PostgreSQL, стек) — в AGENTS.md и в архитектурном отчёте:
https://claude.ai/code/artifact/1b7a3e19-34b6-4da2-bbd0-21a0dff0a02a

## 1. Границы системы

```
┌──────────────────────── VPS (РФ) ────────────────────────┐
│  Caddy (TLS)                                              │
│   ├── /                → (site)     публичный сайт        │
│   ├── /lk/*            → (cabinet)  личный кабинет        │
│   ├── /admin/*         → (admin)    панель оператора      │
│   ├── /api/auth/*      → Better Auth                      │
│   └── /api/integration/v1/*  → API для 1С (HMAC)          │
│  Next.js (один процесс)  ── Drizzle ──▶ PostgreSQL 16     │
│  cron/worker: ночная сверка, outbox уведомлений, health   │
└───────────────────────────────────────────────────────────┘
                 ▲ только исходящие HTTPS от 1С
┌──────── офис ────────┐
│ 1С + расширение .cfe │  push НСИ/статусов, poll заявок + ACK
└──────────────────────┘
```

Правила границ:
- Страницы (`app/`) тонкие: читают данные через модули, не через Drizzle напрямую
  (исключение — простые RSC-выборки внутри модуля).
- Вся доменная логика — в `src/modules/*` (server-only). Тарифная логика —
  чистые функции без побочных эффектов, покрываются тестами.
- Источник тарифов абстрагирован (`pricing/provider`): сейчас статические
  данные со старого сайта, после обмена с 1С — таблицы `direction_prices`
  и `nomenclature`. UI калькулятора от этой замены не меняется.
- Публичный трекинг никогда не отдаёт ФИО, телефоны и суммы.

## 2. Структура кода (целевая)

```
src/
  app/
    (site)/                публичные страницы, общий layout (header/footer)
    (cabinet)/lk/          ЛК: layout проверяет сессию и роль
    (admin)/admin/         оператор/админ: заказы, пользователи, обмен, контент
    api/auth/[...all]/     Better Auth handler
    api/integration/v1/    эндпоинты для 1С (см. docs/INTEGRATION.md)
  modules/
    catalog/     НСИ: номенклатура, направления, цены, пункты выдачи; upsert по ref_1c
    pricing/     расчёт стоимости: чистые функции + provider (static | db)
    shipments/   грузы, статусы, таймлайн, поиск по трек-коду, status_map
    orders/      заявки ЛК и лид-формы: создание, очередь для 1С, ACK
    integration/ HMAC-проверка, разбор пакетов 1С, sync_log, health
    auth/        конфиг Better Auth, роли, привязка пользователь ↔ контрагент
    notifications/  outbox Telegram/email (этап 3)
  components/
    ui/          shadcn (не редактировать вручную без нужды)
    site/        блоки публичного сайта
    cabinet/     блоки ЛК и админки
  data/          статический контент: тексты, услуги, FAQ (тарифы переезжают в БД)
  db/            schema.ts, index.ts; миграции — в /drizzle
deploy/          docker-compose.yml, Caddyfile, бэкап, .env.example для VPS
docs/            ARCHITECTURE.md, INTEGRATION.md (контракт API для 1С-ника)
1c/              исходники расширения (выгрузка в XML), инструкция по установке
```

Роли: `shipper` (грузоотправитель), `consignee` (грузополучатель),
`operator` (сотрудник компании, видит все заказы), `admin`.
Доступ к заказу — через связь пользователя с контрагентом 1С
(отправитель видит исходящие, получатель — входящие).

## 3. Состояние и дорожная карта

Легенда: ✅ готово · 🟡 частично · ⬜ не начато

### Этап 0 — фундамент
- ✅ Next.js 16 + Tailwind 4 + shadcn, репозиторий, конвенции
- ✅ Схема БД-зеркала (черновик, ещё не применена миграциями)
- ⬜ Хостинг (VPS) + домен + PostgreSQL + миграции применены
- ⬜ CI/CD (GitHub Actions → сборка образа → деплой по SSH)
- ⬜ Ответы 1С-ника: конфигурация, где статусы, тарифная формула, лицензии,
  тестовая копия базы (блокер для этапов 1.3–1.4)
- ⬜ Дизайн-макеты ключевых экранов (Claude Design) → единая палитра в globals.css

### Этап 1 — публичный сайт на живых данных
- 🟡 Страницы: главная, услуги, тарифы, контакты, о компании, политика,
  калькулятор, трекинг — свёрстаны, но работают на статических данных
  (`src/data/*`), трекинг — на демо-грузах
- ⬜ 1.1 Подключить БД: трекинг ← `shipments`+`shipment_events`,
  пункты выдачи ← `pickup_points`, калькулятор ← provider `db`
- ⬜ 1.2 Заявки → таблица `orders` (сейчас — файл var/leads.jsonl)
- ⬜ 1.3 Интеграционный API `/api/integration/v1`: HMAC, upsert НСИ,
  статусы+события, `orders?status=new`, `orders/{id}/ack`, `health`;
  тесты + мок «1С» для разработки без офиса
- ⬜ 1.4 Расширение 1С (.cfe): очередь, регламентное задание, push/poll;
  установка на тестовую копию, затем в бой
- ⬜ 1.5 Мониторинг свежести обмена (алерт в Telegram), Uptime Kuma
- ⬜ 1.6 Главная и калькулятор — доводка композиции по дизайн-спеке референса

### Этап 2 — личный кабинет
- ⬜ 2.1 Better Auth: таблицы, вход по телефону/email, роли, сессии
- ⬜ 2.2 Привязка пользователя к контрагенту (подтверждение оператором)
- ⬜ 2.3 Журнал заказов по роли, карточка заказа с таймлайном и детализацией услуг
- ⬜ 2.4 Оформление заказа из калькулятора → `orders` → 1С → номер клиенту
- ⬜ 2.5 Панель оператора: заказы, пользователи и привязки, журнал обмена,
  контент (новости, пункты выдачи)

### Этап 3 — сервис и рост
- ⬜ Уведомления о смене статуса (Telegram/email; SMS позже)
- ⬜ Документы в ЛК (счета, акты), взаиморасчёты
- ⬜ Онлайн-оплата (ЮKassa/СБП) — при подтверждённой потребности
- ⬜ SEO-страницы направлений «Грузоперевозки {А} — {Б}», мультитрекинг

## 4. Порядок работы с Claude Design

1. Экран проектируется в Claude Design (canvas) на токенах проекта:
   primary `#1D327B`, accent `#E10818`, фон карточек `#F0F0F0`,
   радиус 8px, шрифт Inter Tight.
2. Утверждённый макет → реализация в Next.js в этой сессии, компоненты
   складываются в `components/site` или `components/cabinet`.
3. Очередность экранов: главная (композиция референса) → калькулятор-мастер →
   страница трекинга → ЛК (журнал, карточка заказа) → панель оператора.
